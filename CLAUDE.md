## Build & Run

```bash
dotnet build
dotnet run                          # defaults to http profile
dotnet run --launch-profile https   # https://localhost:7171
```

Default HTTP port: `http://localhost:5126`

## Frontend Assets

Static assets live in `wwwroot/`. GOV.UK Frontend is installed via npm:

```bash
cd wwwroot
npm install
npm run build   # compiles SCSS and processes GOV.UK Frontend assets
```

## Health Check

A `/health` endpoint is registered and responds to GET requests — useful when verifying the app is running.

## Architecture

**ASP.NET Core 10.0 Razor Pages** application targeting UK government digital standards.

- `Program.cs` — entry point; configures Serilog (compact JSON to console)
- `Startup.cs` — service registration and middleware pipeline
- `Pages/` — Razor Pages following the `.cshtml` + `.cshtml.cs` code-behind pattern
- `Pages/Shared/_Layout.cshtml` — master layout built on [GOV.UK Frontend](https://design-system.service.gov.uk/)
- `wwwroot/` — static files; `govuk-frontend` npm package provides CSS/JS assets

**Service registrations** (Startup.cs): Application Insights (conditional on connection string), session, HTTP context accessor, health checks, Razor Pages.

**Middleware order**: exception handler → HTTPS redirect → health checks → static files → session → Razor Pages routing.

## Key Conventions

- Namespace: `Dfe.UnifiedIntake.Pages` for page models
- Error handling routes to `/Errors` (note: plural) with status code query param
- Application Insights is only wired up when `APPLICATIONINSIGHTS_CONNECTION_STRING` is set
- GOV.UK Frontend JS is initialised via ES module imports in `wwwroot/js/site.js`
- Static asset cache-busting uses `asp-append-version="true"` tag helper attribute
